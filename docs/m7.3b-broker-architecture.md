# M7.3b.3: broker-spawned directory worker (architecture note)

Status: implemented as a library slice on `feat/m7.3b3-broker-worker`, uncommitted. **Not wired into the product**: no MCP
tool starts it, `sandbox::enter` still `exec`s (no surviving stage 1), and the real sandboxed frontend does not yet have a
broker descriptor. Labels: **VERIFIED** (a test or measurement in this branch), **REASONED**, **UNKNOWN**.
This note extends `docs/design-m7.3b-dynamic-workers.md` (sections 3, 4a, 4b, 5) and does not replace it. The authority model
(A0 verified, A1 configured, grants written by `mind grant`) is unchanged: **a same-user shell agent that can run `mind grant`
is outside every guarantee here, and a broker "authorization" is the grant store's state, not human consent.**

## 1. Process topology (what exists)

```
 frontend (database owner, MCP)            broker (library, runs in its own process)          worker (one per operation)
 Landlock: static roots + db dir           NOT in the frontend's Landlock domain               own Landlock: system read + ONE root fd
 seccomp socket-deny                       reads trusted authority state per operation         own seccomp socket-deny, no-new-privs
        │  Begin{op,kind,root,spaces}              opens + pins the root, makes the cgroup               ▲ fd 3 channel, fd 4 root, fd 5 control
        ├──────────────────────────────────────────▶ spawns worker into the cgroup ────────────────────────┤
        │                                           waits READY, observes /proc, sends GO ◀── READY (after confinement)
        │◀── Ready{observed,...} + channel fd (SCM_RIGHTS)
        │◀══════════ hello, manifest, context, record stream (existing protocol, frontend ⇄ worker, NOT relayed) ═════▶
        ├── Done | Cancel | hang-up ───────────────▶ cgroup.kill, reap, report
        │◀── Finished{exit, exited_by_itself, descendants_killed, peak}
```

The broker never relays the record stream and never sees the database. The frontend reads the worker's channel directly,
runs the existing context exchange (`worker::context`, with the placeholder-provenance check) and persists only after the
whole result validated. Code: `src/worker/broker.rs` (broker), `worker::client::extract_via_broker` (frontend side),
`worker::run` (control handshake).

**Not built (and why it matters).** The design's "stage 1 stays alive" requires changing `sandbox::enter` from `exec` to
fork-and-stay, passing one allowlisted descriptor through `close_inherited_fds` and `verify_stage2`, and a broker role in
`mind mcp --grants`. That edits the code that creates the frontend's sandbox; it is a separate, reviewed change. In the
tests the broker runs in the unconfined test process and the "frontend" is the code at the other end of a socketpair:
**the property "the frontend is Landlock-confined while the broker is not" is therefore REASONED from the design and from
`docs/m7.3b-frontend-spawn-gate.md` (an fd does not override a Landlock domain), not exercised end to end here.**

## 2. Trust boundaries

| Party | Trusts | Is trusted for |
|---|---|---|
| Broker | the kernel; the authority source (static roots, grant store) | nothing the frontend or worker says. Opens roots itself; decides limits; observes the worker |
| Frontend | the broker's observation of the worker; its own validation | the database, spaces, persistence |
| Worker | only fd 4 (root, read-only via its own Landlock rule) and its request | parsing hostile content; its output is untrusted data |

## 3. Broker/frontend IPC (closed vocabulary)

JSON lines, ≤ 8 KiB, strict (`deny_unknown_fields`): `Begin{v, op, kind=directory_extract, root, spaces}`, `Done`, `Cancel`.
There is no field for a grant id, access mode, ttl, limit, descriptor or "approved" claim (VERIFIED: five such extras are
refused as unreadable). `Ready` carries the channel as one SCM_RIGHTS descriptor; the receiver refuses truncated messages
and more than one descriptor.

Binding of an operation: operation id (single use; replay refused, last 4096 remembered), operation type (one value),
authority source (`static` or `grant:<id>`, derived by the broker, returned for audit), root (exact string match against the
authorized path; echoed and re-checked by the frontend), spaces (validated, echoed, re-checked; the frontend alone resolves
them and sends them to the worker; the worker cannot choose), limits (broker configuration only). Cross-operation replay of a
placeholder is closed by the context check (`tests/placeholder_provenance.rs`) and by op-bound stream frames.

## 4. Grant binding, revocation, root descriptor

* Authority is `RootAuthority::roots()`, evaluated for **every** operation: `StaticRoots` (pinned device/inode at start) or
  `GrantRoots` (`grants::resolve_for_start` now: active, path policy, device/inode as approved). A revoked grant is refused at
  the next `Begin` (VERIFIED, real grant store). **Revocation of a running operation is NOT implemented** (the design's 1 s
  re-check): a running operation ends at its wall-clock limit, on `Cancel`, or when the frontend hangs up. UNKNOWN effort, small.
* The frontend only names a path. The broker requires an exact match with an authorized path (a subdirectory, a parent, `x/..`
  and a symlink to the root are refused: VERIFIED), opens it with `openat2(RESOLVE_NO_SYMLINKS)`, compares device/inode with
  the approved identity, compares `/proc/self/fd/N` with the authorized path, and re-opens a read descriptor **from that
  descriptor** (`openat(fd, ".")`), so no path is resolved a second time. Replacing the directory or putting a symlink at the
  path after authorization fails (VERIFIED).
* Ownership: the broker owns the root descriptor from open to spawn; the worker inherits one copy as fd 4; the broker closes its
  copies right after the spawn. The frontend never holds a root descriptor.

## 5. Worker lifecycle

Spawn (cleared environment, own process group, `PDEATHSIG`, core dumps off, optional `RLIMIT_AS`/`RLIMIT_CPU`, joins the
operation's cgroup **before exec** by writing `0` to `cgroup.procs` between fork and exec, exactly fds 3/4/5) → worker closes
everything else, enters its sandbox, reports `READY` → broker observes → `GO` → channel to the frontend → supervise → `Done`
(wait for a self-exit up to `exit_grace`) / `Cancel` / hang-up / wall clock → SIGKILL to the group, reap the leader with
`wait4` (exit status, peak RSS), `cgroup.kill`, wait for `populated 0`, remove the cgroup → `Finished`.
Concurrency: `max_concurrent` (default 1); more is refused as `busy`, not queued (VERIFIED).
The thread that spawns the worker also supervises it: `PR_SET_PDEATHSIG` is tied to the spawning thread.

### Descendants (the known blocker) — VERIFIED
`cgroup.kill` ends a descendant that called `setsid` (stand-in worker, `a_setsid_descendant_does_not_survive_cgroup_cleanup`).
The experimental `UnreliableProcessGroupOnly` mode leaves the same descendant running (demonstrated, then killed by the test),
and every result in that mode says `cleanup: process_group_only`. A subreaper was evaluated and **not used**: it only changes
who adopts orphans; it kills nothing, and `waitpid(-1)` in a library broker would steal other children's statuses.
`cgroup.kill` needs Linux 5.14 and a writable cgroup v2 subtree.

### Failure when cgroups are unavailable
`Broker::new` with `CleanupPolicy::Cgroup` (the default) returns an error; there is no silent downgrade. The process-group
mode must be chosen by name. **The fail-closed path itself could not be exercised here** (this machine has delegation; it cannot
be removed from inside a test): REASONED from the code, not VERIFIED.

## 6. Resource accounting

| Concern | Mechanism | Status |
|---|---|---|
| Per-process address space | `RLIMIT_AS` (`rlimit_as_mib`) | experimental, default off; **no approved production value** (1 GiB was a test value) |
| Aggregate memory | `memory.max` (+`memory.swap.max=0`, `memory.oom.group=1`) on the operation cgroup | VERIFIED: a 64 MiB limit ends the slow-parse operation, broker survives, a small operation reports `memory.peak` ≤ limit. Requires the memory controller; a requested limit without it **refuses the operation** |
| Process count | `pids.max` | configured in that test; no test that exceeds it (UNKNOWN) |
| CPU | `RLIMIT_CPU` + wall clock; no `cpu` controller on this machine | wall clock VERIFIED (timeout), `RLIMIT_CPU` not tested |
| Wall clock | broker `wall_timeout` (hard) + frontend idle/wall guards | VERIFIED |
| Cancellation | frontend flag → `Cancel` → kill | VERIFIED (latency in the report) |
| Concurrency | `max_concurrent` | VERIFIED |

Controller delegation: a cgroup that holds processes cannot delegate controllers, so the broker moves **itself** into
`<base>/supervisor` and puts operations beside it. On this machine the terminal's scope had no controllers; the sibling
position (the slice) did, and `create` falls back to it. **Moving the broker process out of its systemd unit changes that
unit's accounting and is intrusive for a production broker; whether a user service with `Delegate=yes` is the right home is
UNKNOWN.** Trees of brokers that died without cleanup are swept (empty, dead pid) at the next start.

## 7. What can be observed from outside, and what cannot

Observed by the broker after `READY` and before `GO` (not the worker's word): `Seccomp: 2`, `NoNewPrivs: 1`, `TracerPid: 0`,
`CapEff` all zero, cgroup membership equals the operation's cgroup. The frontend additionally checks that the broker's pid
equals the hello's pid and keeps the existing hello probes.

**Not observable externally:** the Landlock domain and its rules (no `/proc` entry), the worker's descriptor table (it is not
dumpable, so `/proc/<pid>/fd` is closed to us), and *when* the worker confined itself relative to reading input. These rest on
the worker's startup sequence (confine, then report `READY`, then read anything) plus the kernel-enforcement tests of the
worker (`seccomp_isolation`, `extraction_worker`, `frontend_spawn_gate`) and the worker's own post-confinement probes in the
hello. A compromised **binary** (the worker executable) is outside this model; `/proc` status alone does not prove the
intended Landlock rules.

## 8. Failure handling (all end in an error for that operation; nothing persisted)

Refused before any process starts: bad version, unauthorized or substituted root, replayed op id, unknown space, busy, no
cgroup for a required limit. After start: no `READY` in time / not confined / wrong cgroup (killed, refused), worker crash,
timeout, cancel, frontend hang-up, malformed stream, memory limit. The broker serves the next operation on the same connection
after every one of these (VERIFIED for crash and memory limit).

## 9. Security limitations (honest list)

1. Production wiring (stage 1 stays alive, one allowlisted fd in `verify_stage2`) is not implemented; end-to-end "confined
   frontend + unconfined broker" is not tested.
2. Placeholder provenance is closed; **semantic correctness of a fresh parse is not** (`docs/m7.3b-context-exchange.md`).
3. A worker can read everything in its authorized root, including secrets inside it, and may fabricate derivations for it.
4. Revocation does not stop a running operation (§4).
5. Landlock is not externally observable (§7).
6. The worker's stderr is discarded in the broker path (diagnostics lost; the frontend sees only the exit status).
7. Linux-only; cgroup v2 with delegation and `cgroup.kill` (5.14+).
8. Git extraction, git children, and non-directory operations are out of scope and untouched.
