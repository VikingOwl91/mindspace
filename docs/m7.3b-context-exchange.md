# M7.3b.2c: Git-less context exchange (directory worker)

Status: implemented on `feat/m7.3b2c-context-exchange`; directory extraction only. Not wired into any MCP
tool. Labels: VERIFIED (a test or measurement in this branch), REASONED, UNKNOWN.

## Why it is needed

The worker has no database, so it cannot ask "was this blob already parsed?" (`has_code_derivation`). Without an
answer it would re-parse every file on every run and send full derivations the parent already has. The
in-process rule (`structural_derivation`: complete identity first, then the skip identities of the current
policy, then parse) must give the same decisions in the worker.

## Protocol (version 2, `worker::PROTOCOL`; there is no version-1 fallback)

All messages are one JSON line (UTF-8, `\n`-terminated), strict (`deny_unknown_fields`), half duplex, before
the record stream. Every message carries the operation id `op` chosen by the parent.

| step | direction | message | content |
|---|---|---|---|
| 1 | worker → parent | hello | pid and sandbox report (unchanged) |
| 2 | parent → worker | `Request` | `v, op, root, spaces[], max_blob_bytes, max_source_bytes, max_entity_depth, max_output_bytes` |
| 3 | worker → parent | `Manifest` | `v, op, entries[{language, hash}]`: the distinct source blobs of the directory |
| 4 | parent → worker | `Context` | `v, op, identities[], known[[hash, identity index]]`: only the hits |
| 5 | worker → parent | record stream | frames bound to `op` (unchanged format) |

Context sent to the worker: space identifiers (from the parent's own request, never chosen by the worker),
the structural parsing policy (3 numbers), the extraction limit (`max_blob_bytes`), the operation id, and the
known derivations of the blobs the worker itself listed. Nothing else about the database leaves the parent.

The manifest comes from a first pass over the directory in which every blob counts as "known": nothing is
parsed and no output is kept. The second pass answers `has_code_derivation` from the context only.

### Bounds (`worker::context`)

| item | bound |
|---|---|
| manifest entries | 100 000 (= the extraction's file limit); more is an error in the worker |
| manifest line | 16 MiB |
| identities | 4 (current parser identity + the 3 skip identities of the operation's policy) |
| known pairs | 400 000 |
| context line | 32 MiB |
| request line | 64 KiB (unchanged) |
| spaces | 64, no duplicates |

### Validation (both sides, deterministic)

* Version, operation id, bounded sizes before allocation (`take(max + 1)`), no duplicates (manifest entry, known
  pair, identity, space), hashes are 64 lowercase hex characters, identity indexes in range, identities limited
  to those the operation's policy can produce, unknown fields refused.
* Parent, before starting a worker: every space exists in its store (`ContextSource::space_exists`).
* Parent, after the stream: the result's spaces equal the request's; every derivation identity is one the
  operation can produce; a skip derivation must fit the size of its source (`check_result`). All before
  `persist`.
* The worker takes no authority from any message: the root is descriptor 4, the spaces and limits are the
  parent's, and the sandbox is entered before the first byte is read. No filesystem permission changed
  (`sandbox/` is untouched in this branch).

## Evidence (tests/context_exchange.rs, 13 tests)

* Reuse without parsing: a 1.9 MiB source whose parse needs seconds and >128 MiB runs a second time under
  `RLIMIT_AS=128 MiB` (the existing crash test shows that a parse aborts there); it succeeds, `known_sent == 3`,
  the second run takes less than half the first. VERIFIED.
* Equivalence: persisted rows and derivations after (worker, worker) equal (in-process, in-process) on a
  second database, table by table and derivation by derivation. VERIFIED.
* Skip idempotence: an over-budget source gives one `failed` skip row; the second run knows it (identity
  `3+skip(p1:source_bytes>…)`), sends a placeholder and changes no row. VERIFIED.
* Changed policy: strict → skip; same policy again → known; raised budget → re-evaluated (real entities);
  lowered again → the complete derivation wins, no new row (the design rule that a lower budget never
  removes structure). VERIFIED.
* Negative: oversized, truncated, empty, non-JSON, non-UTF-8, wrong-shape contexts; unknown versions; replay
  from another operation; missing, duplicate and conflicting identities; dangling index; bad hash; extra fields
  (`grant`, `root`, `path`, `database`); bad spaces; stalled and cancelled exchanges; crashes before and after
  the manifest; the worker refuses with exit 2 and has streamed nothing; the parent returns
  `WorkerError::Context` / `Died` / `Timeout` / `Cancelled` and the database is unchanged. VERIFIED.

## Limits of the design (honest list)

* **Existence oracle.** The worker can learn whether a derivation exists for a content hash it computed
  itself, up to 100 000 hashes per operation. It cannot ask about content it cannot read. REASONED: low value;
  UNKNOWN whether it matters for a compromised worker.
* **Placeholder provenance (closed in M7.3b.3).** A reuse placeholder is now explicit on the wire
  (`code_input.reused`, default false, directory operations only) and survives assembly
  (`ExtractedFiles.reused`). `check_result(files, op, spaces, policy, sent)` accepts a placeholder only for a
  `(content hash, identity)` pair in the `Context` this operation sent, refuses a "fresh" derivation for content
  announced as known, refuses conflicting decisions for equal content and refuses a reuse that carries structure
  (the assembler also refuses parts after a reused record). Emptiness is never evidence of reuse.
  Tests: `tests/placeholder_provenance.rs`. VERIFIED.
* **Residual trust boundary: fabricated fresh derivations.** Three separate properties:
  1. *Protocol integrity* (framing, op binding, content hash binding, bounds): checked by the assembler. VERIFIED.
  2. *Placeholder provenance*: checked as above. VERIFIED.
  3. *Semantic correctness of a fresh parse*: NOT established. A compromised worker can send a structurally valid
     derivation (empty, or with invented entities) for any blob it can read and the parent did not announce;
     the parent cannot tell it from a parser result without parsing the content itself.
     Pinned by `residual_fabricated_fresh_derivation_is_not_detectable`. The worker is therefore trusted only for
     the content it can read (the authorized root), never for the database; poisoning is limited to derivations
     of blobs of that root. Re-parsing in the parent would close it and defeat the isolation's purpose.
* **Time of check.** A file changing between the two passes has another hash, is not known and is parsed.
  Cost: a re-parse, never a wrong reuse. VERIFIED by construction (lookup is by hash).
* **Double read.** The directory is read and observed twice. Measured (release, `worker_run` on this repository's `src`, 302 records, two runs each): 223–262 ms before, 228–231 ms after: within noise. A large tree (wgpu-size) was not measured (UNKNOWN).
* **Many files.** More than 100 000 source files is an error (the extraction limit is the same).

## Remaining security work

Update (M7.3b.3, `docs/m7.3b-broker-architecture.md`): items 1 to 3 and 5 now have a library-level implementation and
tests (broker with `/proc` and cgroup observation, `cgroup.kill` for escaped descendants, `memory.max`); the production
wiring (stage 1 stays alive) is still open. Item 4 (Git) is untouched. The list below is the original wording.

1. **Broker-controlled worker spawning for dynamic roots**: a child of the frontend can only serve roots in
   the frontend's Landlock domain (see docs/m7.3b-frontend-spawn-gate.md); roots approved later need a broker
   outside that domain.
2. **Independent confinement verification**: the frontend cannot read `/proc/<worker>/status`; with
   `verify_via_proc = false` the worker's hello is the only evidence. Needs a verifier outside the frontend's
   domain (the broker).
3. **Descendant cleanup beyond process groups**: a descendant calling `setsid` survives the group kill. Needs
   a cgroup scope or a subreaper.
4. **Git-child execution and inherited descriptors**: the Git path spawns `git` children; their descriptor
   inheritance, the pinned-root paths via `/proc/<pid>/fd` and the `/proc` narrowing interplay with a worker are
   untested. Git extraction needs its own context (ref state) and tests.
5. **Aggregate resource accounting**: per-process `RLIMIT_AS` and wall/idle limits exist; no limit on total
   memory, CPU or output across concurrent operations, and no cgroup limit by default.
