# M7.3b.2a: the isolated extraction worker (first vertical slice, uncommitted)

Scope: directory extraction only. Nothing calls it from a tool: the in-process ingest is unchanged.
Labels: **Measured** (this host, release build for the timing table), **Reasoned**, **Unknown**.

## Architecture
```text
parent (future MCP frontend)                         worker: `mind extraction-worker` (hidden)
  Anchor (verified root fd) ──dup──► fd 4  ─────────► root directory, read access only
  socketpair ──────────────────────► fd 3  ◄────────► channel
  pre-exec: new process group, PDEATHSIG, RLIMIT_CORE=0 [, RLIMIT_AS], close_range(5..), env cleared, cwd /
                                                      1. NO_NEW_PRIVS, not dumpable, close stray fds
                                                      2. seccomp: socket() denied (existing filter)
                                                      3. Landlock: system libs, own /proc/<pid>, /dev/null,
                                                         + read (files, listing) beneath the root fd; no write,
                                                         no execute, no sibling, no database, no grants, no Git
                                                      4. self-test by observation, then hello line (json)
  checks hello + /proc/<pid>/status (Seccomp 2, NoNewPrivs 1, TracerPid 0, pid matches)
  request line (json): op, root, spaces, limits, policy ──►
                                                      5. stream_directory → bounded record stream (fd 3)
  consume(): validates every record, checks the closing counts ◄── frames
  returns Extracted ONLY after a complete valid stream and a clean exit; kills the whole process group always
  the caller persists (the worker never sees the database or the grant store)
```
* Code: `src/worker/{mod,run,client}.rs`, `sandbox::enter_extraction_worker`, `seccomp::apply_allowing`,
  `Anchor::{from_verified_fd, dup_fd}`, hidden `mind extraction-worker`, examples `worker_probe` (test support) and
  `worker_run` (measurements).
* The worker cannot choose its authority: its root is the descriptor it was handed; the request only names it
  (the worker checks that the descriptor really is that directory); spaces, limits and the policy come from the parent.
* The worker has no database context: it always parses source files (no `has_code_derivation` shortcut); the parent's
  persistence reuses what exists. The shortcut needs the context exchange of M7.3b.2b.

## Isolation evidence (tests/extraction_worker.rs, 13 tests; all pass)
* The worker's result equals the in-process extraction (full debug dump, ids and times masked) and persists to
  the same row counts.
* Kernel-level probes run through `sandbox::enter_extraction_worker` in a helper process with the same descriptors:
  EACCES for a sibling repository (directly and via `..`), the database file, the grant store, another file next to
  the root, `/etc/passwd`, `/home`, `/tmp`, `/root`, `/proc/1/environ`, another process's `environ` (the parent's), the process
  list, writing and creating files inside the root, writing in `/tmp`; EACCES for `socket()` in AF_INET, AF_INET6,
  AF_UNIX and AF_NETLINK; an inherited descriptor to a secret file (left open by the caller) is EBADF; positive controls
  (reading and listing the root) work.
* The real worker reports the same probes in its hello (denied/allowed as required) and the parent verifies the
  kernel's view of the process; a worker that is not confined (wrong pid, no evidence) is refused.
* A repository containing symlinks to the database, to a relative `../mind.db` and to `/etc/passwd` yields none of their bytes.
* Not verified from outside: the worker's descriptor table (it is not dumpable, so `/proc/<pid>/fd` is closed to
  the parent; checking it is deliberately not attempted). It is covered by the pre-exec `close_range`, the worker's own
  close, and the probe above.

## Failures (all with the parent alive, the worker and its group gone, the database unchanged)
Crash by `RLIMIT_AS` (128 MiB, parse needs several hundred): "ended (killed by signal 6)"; hard wall clock while
the worker is busy in an uninterruptible parse: stops at the limit (1,000 ms limit -> 1,047 ms); cancellation: 300 ms
after the flag -> 327 ms; SIGKILL of the worker after several MiB of frames reached the parent: "killed by signal 9",
stream refused, nothing persisted, a second extraction then works; fake workers: early exit, garbage instead of frames
(frame length refused), a replayed frame of another operation, silence (idle limit), a child process of the worker (ended
with the group).

* Worker start-up (spawn to verified hello): 3 ms.
* In-process extraction of the 30k files took 0.45 s earlier; the worker run is slower here (0.7-0.9 s: no
  `has_code_derivation`, 28 MB of JSON, validation in the parent); not tuned.
* Aggregate cgroup limit (Measured with the worker started inside `systemd-run --user --scope -p MemoryMax=...`,
  the parent outside): 2 MiB array at 300M: worker SIGKILLed by the cgroup, parent alive, no result; at 1G ok; 30k files at 300M ok;
  1G with `RLIMIT_AS` 1 GiB ok. The sandbox hello is still verified inside the scope (the pid is the worker's: the scope
  execs the command; descriptors 3 and 4 pass through). This used a wrapper command, not a feature of the client.
* Intended protection versus measured: `RLIMIT_AS` bounds the worker's address space (it aborts, it does not degrade) and
  does not bound resident memory or the sum over workers; the cgroup bounds resident memory of the group and kills.
  No production value is declared: 1 GiB passed every fixture here, 512 MiB failed the 2 MiB hostile ones.
* Git children: this slice starts none; the group kill was demonstrated with a shell child. Git extraction is not in
  the slice.

## Known limits and blockers for M7.3b.2b
* No context exchange (`has_code_derivation`, spaces by name, `git_refs_current`): needed for repeat-ingest speed and Git.
* Git extraction in the worker (read-only repository, identity marker created by the frontend or at grant time,
  Git children and their termination).
* Parent-death behaviour (`PR_SET_PDEATHSIG`) is set but not tested; the pdeathsig is tied to the spawning thread.
* The client is not used by `mind mcp`/`mind ingest`; the grant-driven choice of root, the broker, and the structural
  progress/skip options are untouched.
* Landlock ABI 6 signal scope is active here (kernel 7.2); on older kernels the worker reports `signal_scope: false`.
* The worker prints errors to its stderr (bounded to 8 KiB by the parent); there is no structured error channel yet.

## Preparation for M7.3b.2b (documented, nothing implemented)

### 1. Parent-death race and thread lifetime
* `PR_SET_PDEATHSIG(SIGKILL)` is set in the child between fork and exec. Measured: with the harness as parent, SIGKILL of the
  parent while the worker was parsing ended the worker 40 ms later.
* Open: (a) the race where the parent dies between `fork` and `prctl` (man prctl: the signal is not sent for a parent that
  is already gone; the child must compare `getppid()` with the parent's pid captured before the fork and exit if it
  differs); (b) the signal is tied to the **thread** that forked, not the process: if the MCP server forks the worker from a
  short-lived thread, the worker dies when that thread ends. The client must be called from the thread that waits for it (as
  `extract_directory` does), and the MCP wiring must not hand a spawn to a thread pool worker that can exit.
* Tests to write: kill the parent immediately after spawn (loop, many iterations); spawn from a thread that exits while the
  worker runs (expected: worker dies, parent reports an error, nothing persisted); parent SIGKILL during each phase
  (hello, request, stream).

### 2. Process-tree cleanup for Git children
* Today the whole process group is killed after the worker is reaped or on any error (demonstrated with a shell child).
* Open: a descendant that calls `setsid` or `setpgid` leaves the group and survives. Options to evaluate: kill by cgroup
  (`cgroup.kill`, needs delegation), make the worker a child subreaper (`PR_SET_CHILD_SUBREAPER`) and walk its descendants
  before the final kill, or deny `setsid`/`setpgid` in the worker's seccomp filter for Git children.
* Git children inherit the worker's Landlock domain and seccomp filter and the `RLIMIT_AS`; they need Execute on the resolved
  Git binary (the file rule from the runtime-rules work), the exec-path directory, no `/etc`, and, because the worker is not
  dumpable, the inherited-descriptor form of the pinned roots (`/proc/self/fd/N` in the child, CLOEXEC cleared;
  measured as workable in the Part D findings), not `/proc/<worker>/fd/N`.
* Measured so far for Git children under limits: they need at least 128 MiB of address space on the wgpu clone (fail at 96 MiB).
* Tests to write: a Git child blocked on stdin, on a lock file, and one that daemonizes; the group is gone after timeout,
  cancel, parent death and worker crash.

### 3. Hello limitations and confinement diagnostics
* The hello is the worker's statement. The parent confirms `Seccomp: 2`, `NoNewPrivs: 1`, no tracer and the pid from
  `/proc/<pid>/status`. It cannot confirm Landlock from outside (no `/proc` indicator) nor non-dumpability, and it cannot
  list the worker's descriptors (non-dumpable). A worker compromised before it sends the hello could lie; the protection
  there is the integrity of the `mind` binary the parent executes.
* `signal_scope` in the hello is derived from the ABI number, not observed; the MCP sandbox observes it with a canary
  process. The worker has no canary yet.
* A refused confinement is reported only as exit code 78 plus a bounded stderr line; there is no structured refusal in
  the hello (the hello is not sent at all). The probe list is fixed and small.
* Diagnostics to add: kernel and Landlock ABI in the hello, the signal-scope canary, a structured `refused` message, and
  `doctor` output for the worker (can it start, what does it report).

### 4. Context exchange (known derivations, refs, spaces)
* The worker has no database. It needs `has_code_derivation` (per source, three more probes for skip identities),
  `git_refs_current` (once) and spaces (resolved by the parent: already passed as ids).
* Design: refs go in the request (bounded, once). Derivation knowledge is a batched request/reply on the same channel:
  the worker sends a `context_request` record with up to N keys `(content hash or blob oid, identities)` and waits; the parent's
  stream reader answers with a `context_reply` of one status per key (known complete / known skip with reason / unknown).
  The worker must never block unboundedly: the parent applies a per-operation cap on requests and bytes, treats every
  request as untrusted input, answers from read-only store calls, and never lets a reply carry data beyond statuses.
* Cost to check: request round trips for 60k-file repositories (batching is mandatory) and the deadlock case (the worker waits for
  a reply while the parent waits for frames: the parent's reader must be the only place requests are served).

### 5. Structured worker errors and progress
* Today: exit code (0, 2, 78) and up to 8 KiB of stderr. Design: an `error` record in the stream
  (`code`, `stage`, message <= 4 KiB) sent before a non-zero exit, a `refused` record instead of the hello when
  the confinement fails, and the `progress` record of the structural-policy design (path, blob, size, latest only) before
  large parses. All diagnostic, none authoritative; the parent maps them to `WorkerError` variants.

### 6. Repository identity without unauthorized writes
* The worker's root is read-only; creating `.git/mindspace-repository-id` is a write, so the worker never does it.
* Design: the worker reads the marker; if it is missing it sends a typed `needs_identity` record and ends the stream.
  The frontend, which holds the write authority of the grant (if any), creates the marker through its own verified
  descriptor (O_EXCL, as today) or the grant creation does it up front, and the extraction is repeated. A read-only grant
  on an unmarked repository fails with an explicit message rather than guessing an identity.

### 7. Memory and timeout policy
* Measured: 1 GiB `RLIMIT_AS` passes every fixture of this slice (hostile 2 MiB sources need about 770 MiB of address
  space), 512 MiB does not; a cgroup limit applied to the worker only (outside the parent) kills it without touching the parent.
* Open decisions: default `RLIMIT_AS` (and a different value when Git children run), whether the cgroup limit becomes a
  client feature or a deployment wrapper (it needs a delegated user manager; the client cannot create sub-cgroups itself), what
  happens when a cgroup is unavailable (fail closed or run with `RLIMIT_AS` only, reported in the result), the concurrency
  limit (memory is the sum over workers), wall-clock = the operation deadline of the MCP tool, idle limit (60 s now), and
  the mapping of a kill by `RLIMIT_AS`/cgroup to an explicit "resource limit" error.

### 8. Integration with the broker and grants
* The worker gets a verified descriptor, never a path or the grant store: no Landlock rule exists for the data or
  grant directories, and the tests prove those reads fail. The grant decision (stage 1 of `mind mcp --grants`, device/inode
  identity of each granted root, `open_verified_dir`) stays in the frontend; its `Anchor` is what the client duplicates.
* Access mode: the client always gives the worker read access; a read-write grant changes nothing for extraction.
* Unverified: spawning the worker from inside the MCP frontend's own sandbox (Landlock plus the seccomp filter, signal scope on
  ABI 6). Expected to work (the frontend may exec its own binary, `socketpair` is allowed by the filter, signals to a child
  domain are not scoped), but it has not been run; the first wiring step is an integration test of exactly that, including the
  group kill from the sandboxed parent.
* Dynamic grants (just-in-time approval, broker): the broker decides and hands the frontend a root; nothing about the worker
  protocol changes. The worker request must name the grant epoch so a revoked grant cannot start new work (frontend side).
