# M7.3b.5d: the Git worker, broker-spawned (implemented)

Status: implemented as a library, a hidden CLI mode and test harnesses. **No MCP tool exposes it** (5e), and the broker that
`mind mcp --broker` starts is not given a git executable in a production build, so a Git operation is refused there. Labels:
**VERIFIED** (observed in a test named here), **REASONED**, **UNKNOWN**. Basis: `design-m7.3b5-git-worker.md`,
`m7.3b5b-confined-git-reader.md`, `m7.3b5c-verified-git-transport.md`.

## 2. Authority

* **The broker authorizes the exact root and the operation.** `Begin { kind: git_extract, root, spaces }`; the root must equal one of the broker's own
  authorized roots (static or grant), is opened by the broker with `openat2` and pinned by device/inode, exactly as for directories. A frontend can
  neither name a descriptor nor a grant.
* **The mode is the broker's decision.** The worker's argv is built by the broker from the operation kind. A Git operation on a broker without a
  git executable is refused (`git extraction is not configured on this broker`): no in-process fallback exists. VERIFIED:
  `git_is_refused_without_configuration...`; mutation A2 (a Git operation starting the directory worker) is caught by 14 tests.
* **Execute authority.** The broker is configured with a `GitExecutable` (validated absolute ELF binary + interpreter). The worker re-resolves it from
  argv BEFORE it confines itself; its Landlock domain allows reading the root and the system directories (read/list only, no execute anywhere since the
  stabilization) and EXECUTING exactly those two files. Every git child inherits that domain. VERIFIED by `tests/git_confined.rs` (a worker cannot
  execute `/bin/sh` or anything else; 14 attempts refused) and by the sanity mutation A3 (without the grant git cannot run: 13 tests fail).
* **Root access is a descriptor.** The worker receives the verified root as descriptor 4 and the reader opens everything beneath it; git children inherit
  one descriptor and use `GIT_DIR=/proc/self/fd/N`.
* **Fail closed.** No usable cgroup containment: the broker does not start and the operation is refused with `the broker is not available` (no worker,
  no sibling-cgroup placement, no process-group fallback): VERIFIED `without_usable_cgroup_containment_the_git_operation_is_refused_and_runs_nothing`.

## 3. Repository identity

* The broker, before any worker exists, checks the layout (`check_layout`: a real `.git` directory; no `commondir`, no `worktrees`, no alternates, no
  grafts, no links among the top-level entries) and reads `.git/mindspace-repository-id` with `openat(O_NOFOLLOW)` through the pinned root (never created,
  at most 256 bytes, a UUID). VERIFIED: seven refusal cases leave no worker (`observe_pid` stays 0) and the database unchanged; mutation A1
  (alternates no longer refused) is caught.
* The broker puts that identity into `Ready` and into the worker's argv. The frontend binds the manifest, the context and the result to the BROKER's
  value: the manifest is refused if it names another repository, the stream's header and every code input must carry it, the result must be for the
  head the manifest named. The worker also reads the marker itself and refuses to continue if it differs from the identity it was told (mutation C1 caught).
* Root substitution: the worker's stream names a root; the client requires it to be the root the broker authorized (`repository_path` and `session.root`).
* Unsupported object formats: the confined reader refuses at `open` (the broker runs no git and cannot know), the worker exits, the client reports an error;
  VERIFIED nothing is persisted and the repository is untouched.
* **Preserved limitation:** the marker is repository content. A hostile repository can ship a marker equal to another repository's identity; nothing here
  authenticates it. It binds the operation to *what the marker says*, not to who made it.

## 4. Context exchange and placeholders

```
frontend -> worker   Request     v, op, root, spaces, limits
worker   -> frontend GitManifest v, op, repository_id, head, entries[{language, blob_oid}]
frontend -> worker   GitContext  v, op, repository_id, head, identities[..], known[[blob_oid, identity index]..]
worker   -> frontend verified stream (frames bound to op)
```

* Bound to: the operation, the repository (the broker's), the head the manifest named, and the extractor version through the identities (`mind-code@4`; a
  derivation of another version is never announced). Both sides validate strictly (unknown fields refused, duplicate/malformed entries refused).
* A reuse placeholder is valid only for a `(blob id, identity)` pair that THIS context announced. The store is asked once, when the manifest is answered;
  existence of an id in the store is never evidence at the end. A fresh derivation for an announced blob is refused too.
* The 5c rule stays: a placeholder's content still travels and must hash to its blob id in the same stream.
* VERIFIED (`tests/git_context.rs`, `tests/git_broker.rs`): missing (nothing announced), forged (worker claims everything known), stale (`@3` announcement
  against a `@4` placeholder; `@3` rows are not announced at all), replayed or cross-operation (another operation's context or stream), wrong repository.
  Mutations C2–C10 are caught.

## 5. Lifecycle and persistence

Reused unchanged: the watchdog, the cgroup per operation, supervision, the revocation recheck every 100 ms, the commit lease. `persist_git_with_lease`
applies the lease to the 5a transaction: the broker is asked immediately before the COMMIT, a denial rolls the transaction back, `CommitBegin` extends the lease
to the in-flight ceiling, `CommitDone` releases it. Outcomes: COMMITTED, ROLLED_BACK, UNKNOWN (`CommitOutcomeUnknown`) as before.

VERIFIED (`tests/git_broker.rs`, `tests/git_broker_mcp.rs`):

| Case | Result |
|---|---|
| normal completion | observed `seccomp=2`, no-new-privs, no tracer, no capabilities, cgroup `/op-…`; one recording revision |
| worker crash | an error; the broker serves the next operation; nothing persisted |
| worker timeout (broker wall clock) | `Timeout`; worker AND its blocked git child gone |
| cancel | `Cancelled`; worker and git child gone |
| revocation during extraction | `Revoked`; worker and git child gone |
| revocation before persistence | the lease is denied (`revoked`); the transaction rolled back; rows unchanged; **no recording revision consumed** |
| a commit that outlasts the grant ceiling | the lease is kept (`CommitBegin`); a revocation (another process) waits and completes only after the commit; mutation L2 caught |
| vetoed SQLite commit | clean rollback, no revision, the handle stays usable |
| lost acknowledgement | `CommitOutcomeUnknown`; the data is committed; a retry adds no derived structure |
| malformed / oversized / truncated stream, wrong op, wrong head, wrong root, forged reuse, lying identity | refused, nothing persisted, worker gone, the next honest operation succeeds |
| broker SIGKILL / frontend SIGKILL during an operation | worker, its git child and the cgroup tree are gone, the watchdog exits; the frontend is told / not affected |
| repeated ingestion | announced placeholders; the derived structure does not grow; an extractor change re-derives once and settles |

  A1 alternates not refused, A2 Git starts the directory worker, A3 no execute grant, C1 worker accepts any identity, C2 manifest not bound to the
  broker's identity, C3 result may name another repository, C4 placeholder need not be announced, C5 head need not match, C6 fresh derivation for an
  announced blob, C7 other spaces, C8 root label unchecked, C9 stream of another operation, C10 worker validates no context, L1 a denied lease still
  commits, L2 `commit_begin` skipped (first SURVIVED, which exposed that revocation ordering was untested; `a_commit_that_outlasts_the_grant_ceiling...`
  now catches it). The 5c verifier has its own 12 (see that document).
* `systemd-run --user`, `Delegate=yes` and `Delegate=no`: `git_broker` (17) and `git_broker_mcp` (4) pass in both; the worker runs inside the frontend's
  cgroup in the production start-up (`git_broker_mcp`), and `tests/scripts/systemd_git_containment.sh` shows frontend, watchdog, worker and git child
  all INSIDE the unit, all gone after `kill -9` of the watchdog, and the unit stopping cleanly (6-57 ms), for both settings. (The in-process
  `Broker::new` used by `git_broker` may place its tree beside the original cgroup when controllers are wanted; that is the library/test form, not the
  production start-up.)

## 7. Final review (before the commit)

The full diff was read, including every deleted line (all deletions are the refactor of the layout/marker code into functions, the broker/client plumbing for the operation kind, and
imports; the directory worker's `main()` is untouched). Findings, all fixed or recorded:

1. The directory `Ready` message had started to serialize `"repository_id": null`. Now omitted when absent (test `the_directory_ready_message_has_no_repository_identity_key`).
2. Replay of a Git operation id was untested: `a_git_operation_id_cannot_be_reused_and_the_identity_in_ready_is_the_brokers`.
3. The production-style broker (no git executable) refusing Git was tested only in-process: now also through the real process tree
   (`a_broker_started_the_production_way_without_a_git_executable_refuses_every_git_operation`), including that a directory operation still works through it.
4. The executable's pinning was asserted, not shown. Two tests now show it (see `m7.3b5e-mcp-git-tool-plan.md` section 5): a binary REPLACED after the worker confined itself is not
   executed; one MODIFIED IN PLACE still runs (a documented limit, pinned by a test).
5. HEAD: the worker's claim is verified for internal consistency only; nothing here establishes that it is the repository's real HEAD (5c trust assumptions unchanged).

## 8. Not done / limits

* No MCP tool and no production configuration of the git executable (5e).
* The broker cannot check the object format (it runs no git); the worker does.
* The broker check of the layout and the worker's `open` use the same function, but the layout is checked again by the worker, so a repository changed
  between the two is still refused (the worker sees the final state).
* A text blob that is not valid UTF-8 is not interpreted (its bytes could not be carried and verified); its row stays an unverified `(oid, size)`.
* HEAD only; remotes are carried as worker-asserted metadata (see the 5c trust assumptions, which all still apply).
