Status: implemented, **uncommitted for review**. Labels: **VERIFIED** (observed in a named test or run), **REASONED**, **UNKNOWN**.
Basis: `m7.3b5e-mcp-git-tool-plan.md`, `m7.3b5d-git-worker.md`, `m7.3b5c-verified-git-transport.md`, `m7.3b5b-confined-git-reader.md`.

## 1. What exists

| Piece | Where |
|---|---|
| Tool `repo_ingest_git_isolated` (input `path`, `spaces`; closed schema) | `src/mcp/isolated_git.rs`, wired in `mcp/tools.rs` |
| Hidden flags `--isolated-git-ingest`, `--git-exe <PATH>` | `src/cli/mod.rs` (`mind mcp`) |
| Executable trust policy and pins | `src/ingest/confined_git.rs` (`TrustPolicy`, `trusted_resolve`, `GitExecutable::resolve_trusted`, `FilePin`, `verify_pin`) |
| Pin check and descriptor-bound execute rule in the worker | `src/worker/run.rs::main_git`, `src/sandbox/mod.rs::enter_extraction_worker_with_exec_files` |
| Worker argv `--git-pin`, `--interp-pin` | built by the broker (`worker/broker.rs`), parsed in `cli/mod.rs` |
| Stage 1 to broker to stage 2 plumbing | `sandbox::BrokerRequest.git`, `watchdog_main`, `ENV_GIT_APPROVED` |

The pipeline is the 5d one, unchanged and reused: broker authorization of the exact root (static root or revocable grant) -> pinned root -> confined Git
worker -> GitVerified transport -> verification in the frontend (`check_result_git`) -> one atomic SQLite transaction with a broker commit lease
(`persist_git_with_lease`). The tool contains no extraction or persistence logic of its own.

## 2. Gates (all required; any failure means the tool does not exist)

1. `--isolated-git-ingest` (hidden, explicit).
2. `--git-exe <absolute path>` from the administrator. No PATH lookup, no default, never read from a request. Missing: one line on stderr, no tool.
3. The executable passes the trust policy in **stage 1, before the sandbox** (section 3). Failing: one line naming the reason, no tool.
4. Stage 2 verifies the sandbox (Landlock + seccomp, observed) and receives the broker channel. Without both: no tool.
5. The broker (a separate process outside the frontend's domain) authorizes the exact repository root per call (static root, or a grant re-read now).
6. Per call: the worker's cgroup must lie inside the server's cgroup, else nothing is persisted (`containment_not_verified`).

There is no in-process fallback and no shell. The decision travels from stage 1 to stage 2 as `MINDSPACE_SANDBOX_GIT_APPROVED=1`, which stage 1 always
clears first; stage 2 additionally needs the verified broker channel, and the broker itself only has a git executable if stage 1 gave it one
(otherwise every Git operation is refused: `git extraction is not configured on this broker`).

VERIFIED (`tests/mcp_git_isolated.rs`): `the_tool_exists_only_when_every_gate_passes_and_the_default_listing_is_unchanged` (flags in every
partial combination add nothing; the default tool definitions are byte-identical to the list with the feature's flags; the tool is appended last;
the directory tool alone is unchanged), `an_executable_that_fails_the_trust_policy_means_no_tool` (user-owned copy, script, symlink in a user-owned directory, bare name,
missing file, directory), `the_caller_cannot_supply_an_executable_environment_arguments_a_grant_or_a_limit` (11 extra fields and 7 malformed forms refused, database unchanged).

## 3. Git executable trust

### Attacker capabilities (explicit)

| # | Attacker can | Defended? |
|---|---|---|
| A1 | write any file as an unprivileged user other than the owner of the chain, including replacing/renaming path components the policy accepts | yes: every owner must be root (default `TrustPolicy`), no component may be group/other-writable (sticky does not excuse it), symlinks only if owned by a trusted uid |
| A2 | replace the binary (new inode) after stage 1 | yes, detected: pins compare device/inode/size/uid/mode and a SHA-256; the worker refuses to start; and after confinement the Landlock execute rule is bound to the verified inode, so a swapped path cannot run (fail closed) |
| A3 | modify the binary in place before the worker starts | yes, detected by the size/mode/SHA-256 pin (`..before it was confined`) |
| A4 | modify the binary in place **after** the worker confined itself | **no**. The Landlock rule is bound to the inode, so the modified content would execute. This needs the file's owner or root, which the policy excludes (A1). Not cryptographically pinned during execution. |
| A5 | be root, or the owner of a trusted file | out of scope: the policy trusts root; an administrator who controls `/usr/bin/git` controls the system |
| A6 | control the dynamic interpreter (PT_INTERP) | covered like the binary: the raw PT_INTERP path is trust-walked, the resolved interpreter must match, both are pinned and execute-bound |
| A7 | control a hostile repository (content the worker reads) | not this gate; the 5b/5c confinement and verification apply |

### What is guaranteed, and what is not claimed

* Guaranteed (VERIFIED, `tests/git_trust.rs` 8 tests, `tests/git_broker.rs::the_worker_gets_the_pins_and_a_binary_that_changed_before_it_started_never_runs`):
  the production policy accepts only root-owned, non-writable ELF binaries reached through a trusted chain; path replacement and in-place modification
  between stage 1 and the worker's confinement are detected and refuse the operation (`Refused: ... before it was confined`), with the database unchanged;
  restoring the identical bytes in place works; an identical copy at the same path (new inode) is refused.
* **Not claimed:** cryptographically pinned executable *content during execution*; protection against root or the owner; protection against
  modification after confinement (A4); a TOCTOU-free exec. Stage 1's check and the worker's check are a time-of-check sequence, and the window
  between the worker's descriptor verification and the kernel's `execve` of the (inode-bound) path is covered by the Landlock rule, not by a hash.
* Experiments (this kernel, Landlock ABI as installed): executing by file descriptor (`fexecve`) closes the path-swap case but not in-place modification;
  a **memfd copy** would pin the executed bytes but Landlock does **not** restrict exec of a memfd, and the interpreter is still loaded by path. The design
  therefore does not use memfd, and the statement "the worker can execute nothing but git" in the 5b/5d documents is qualified: it holds against path-based
  execution; code already running inside the domain could still `execve` a memfd it filled itself. (That code is already confined by seccomp and no-new-privs,
  and has no network or write access.)
* Decision: **not BLOCKED.** A sufficient production policy is demonstrable on the root-owned system chain (`/usr/bin/git`, `/usr`, `/usr/bin`, `/lib64`, `ld-linux`
  all root-owned, mode 755): VERIFIED by `the_system_git_passes_the_default_root_only_policy_and_is_pinned`. Hosts whose git is not root-owned through the whole chain fail closed.
  A different policy (`TrustPolicy { owners }`) exists as a library parameter only; no flag lets a request or an MCP client select it.

## 4. Results

Success (`structuredContent`): `repository {id, path, identity_source}`, `head {commit, symbolic_ref, scope: "head_only"}`, `persisted: true`,
`commit_state: "COMMITTED"`, `persisted_revision` (the store's current recording revision read right after the commit; the ingestion creates exactly one), `counts`,
`verification {internally_verified, not_verified[], unverified_blob_claims}`, `isolation` (observed seccomp, no-new-privs, capabilities, cgroup, cleanup), `context_exchange`.
The two claims are kept apart: internally verified = every object hashes to its id and the structure is closed; **not verified** = that the commit is the real HEAD, that
SHA-1 was collision-free.

Failure: `error.kind`, `persisted` (`false` or `"unknown"`), `commit_state` (`NOT_STARTED`, `ROLLED_BACK`, `UNKNOWN`). `commit_outcome_unknown` is never reported as rolled back.
Kinds: `invalid_argument`, `unknown_space`, `root_not_authorized`, `identity_missing`, `not_a_repository`, `unsupported_repository`, `unsupported_object_format`, `git_unavailable`,
`too_large`, `result_refused`, `context_refused`, `revoked`, `timeout`, `cancelled`, `worker_failed`, `confinement_not_verified`, `containment_not_verified`, `broker_unavailable`, `busy`,
`replay_refused`, `commit_not_authorized`, `commit_outcome_unknown`, `store_discarded`, `persist_failed`.
The path must be lexically canonical (no `.`, `..`, trailing `/`): the repository path is stored as given. (VERIFIED: a trailing-slash spelling was found to resolve to the authorized root and was
stored non-canonically; the Git tool now refuses such spellings. The directory tool is unchanged.)

## 6. Limitations and compatibility

* **HEAD authenticity:** the worker's claim of which commit is HEAD is verified for internal consistency only (5c).
* **SHA-1:** git's SHA-1 without collision detection; object ids are not collision-resistant.
* **Unsupported:** SHA-256 repositories, bare repositories, linked worktrees (`.git` file, `commondir`, `.git/worktrees`), alternates, grafts, symlinks among top-level entries, repositories without the identity marker (never created by this tool), history (HEAD only), non-UTF-8 text blobs (recorded as `(oid, size)` only).
* **Marker:** repository content; a hostile repository can carry any identity. It binds the operation to what the marker says.
* **Kernel:** Landlock ABI >= 3, seccomp, cgroup v2 with a writable delegated subtree (otherwise the broker does not start and the tool is not usable), `close_range` with CLOEXEC.
* **Git:** tested with 2.56.0; `GIT_NO_LAZY_FETCH` needs git >= 2.44.
* **Backward compatibility:** without the flags nothing changes; with only `--isolated-ingest` the directory tool is unchanged; `--broker` alone adds no tool.
* **Resources:** wall clock (`--ingest-timeout`) and stream limits; no aggregate per-operation memory limit (the unit's `MemoryMax=` covers the tree).
