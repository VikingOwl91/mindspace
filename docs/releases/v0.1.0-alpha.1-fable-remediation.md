## Scope and accepted patch

Baseline: GPG-signed `559539ee74974cd97eb8dd88210203f00b012101`, key fingerprint `0E6699CB48F3941AE28CA88D509F78007F62D5EA`. Tracked worktree and index were initially clean. The audit was an existing untracked input; its SHA-256 is `ddb0f00a8c41c5cb278eebb5b76b611b5ed887aba11a7009457ad9b08d1b2903`. Original tracked/untracked inputs were hash-recorded before mutation. Final preservation checks cover every untouched baseline file, including all historical RC.3 artifacts and retained bytecode.

The accepted plan used shared existing display behavior, clap command visibility, fixed per-input bounds, and a small deterministic Git-blob assembler. No schema, dependency, quota framework or ownership/publication architecture change was needed. Applicability: local Linux CLI, library and stdio MCP; no website or web application is introduced or changed.

- **F-01 fixed:** the existing pure sanitizer is shared portably with grants. Human ingest reports, all legacy/explicit-mode search/recall variants, space traversal, related hits, source paths/titles, action labels, fallback diagnostics and terminal errors replace control/bidi override characters with `?`. Recall line structure and ordinary Unicode remain. Database values, successful JSON representations and exit behavior remain unchanged. An attacker-named invalid-UTF-8 file exercised the error sink.
- **F-03 fixed:** clap hides `ownership` from public help. Explicit private administration remains callable and tested. Supported CLI and 15-tool MCP contracts are retained. No document extraction or publication entrypoint is added.
- **F-02 fixed:** each MCP wire line is bounded to 8 MiB including LF/CRLF (EOF without delimiter counts its bytes). Reading stops at at most the first excess byte and returns the existing transport error before JSON parsing; it does not drain or execute the partial request. Manual `content` and `subject` are each bounded to 1 MiB of decoded UTF-8 at MCP validation and before the storage connection/transaction. Oversized fields use existing tool/storage errors and leave the session usable. Wire and decoded constraints apply independently; maximally escaped individually valid fields may exceed the line bound. Existing oversized records remain readable; updates retaining oversized legacy subjects must provide a smaller subject. No aggregate disk ceiling is promised.
- **F-04 fixed:** ten formerly archive-only inputs now have canonical versioned source. The versioned assembler and explicit `release/source-files.txt` select exact regular Git blobs; both are included in the payload. There are no runtime overlays or temporary/private/developer inputs. Git replacement objects are disabled for every assembler Git command. The manifest records selected members only, omitting historical excluded private filenames/digests.
