## 2. SQLite semantics and selected minimal fix

Cargo.lock retains rusqlite0.40.2 / libsqlite3-sys0.38.2, bundled SQLite3.53.2. The inspected Unix VFS source establishes:

- Default MAIN creation uses0644 reduced by inherited umask (`sqlite3.c:40353–40354,41009–41025`).
- `findCreateFileMode` derives WAL/rollback-journal mode from `stat(MAIN)` (`:46605–46707`).
- SHM creation takes the actual MAIN descriptor's `fstat` mode (`:45165–45224`).
- `robust_open` requests that mode initially; its possible adjustment of an empty sidecar restores MAIN's mode (`:41021–41055`). With MAIN0600 it never introduces group/other access.
- Existing nonempty sidecars are not automatically repaired. A private parent alone can hide them but cannot establish required actual0600 modes.

The locked source is under the local Cargo registry's `libsqlite3-sys-0.38.2/sqlite3/sqlite3.c`; no dependency or SQLite configuration was changed.

The private helper follows one finite sequence:

1. Resolve existing parent aliases to a real absolute path. Before creating directories, require root/effective-UID-controlled ancestry and no group/other writes; root-owned sticky directories are allowed only above a protected immediate parent.
2. Create missing directories with0700 from their first state. Preserve all pre-existing directory modes. Refuse unsafe parents instead of chmod or silent downgrade.
3. Refuse orphan `-wal`, `-shm`, or `-journal` when MAIN is absent. For existing MAIN0600, validate controlled parents and existing sidecars: regular, same UID, single link, no group/other permission bits. Refuse unsafe inputs without chmod/delete or automatic repair.
4. Create a unique empty sibling using `create_new`,0600, O_NOFOLLOW and CLOEXEC; verify its actual mode. Close its descriptor **before** atomically publishing it with `hard_link` to the absent final name. EEXIST preserves a competing initializer's winner. Remove only the owned temporary name.
5. Open canonical MAIN using READ_WRITE/NO_MUTEX/NOFOLLOW, without CREATE or URI interpretation. SQLite cannot recreate a removed MAIN with default0644.
6. Run the unchanged connection initialization/migration sequence.

The closed-sibling sequence matters: closing an independently opened MAIN descriptor after another same-process SQLite connection obtains POSIX locks can release process-associated locks. No separately opened MAIN descriptor is closed after publication. There is no process-wide creation mutex, generic filesystem framework, custom VFS or process-global umask change.

Raw `file:` URI filenames are explicitly refused because SQLite URI routing, `modeof`, VFS and escaping could select a target different from the filesystem path prepared. Ordinary filesystem names containing `?`, `#` and `%` remain literal and work; canonical symlink aliases to existing databases/parents work. Dangling final or parent symlinks fail without creating their target. `open_in_memory` remains the supported explicit in-memory API.

Failed initialization leaves published private MAIN/parents for recovery; it never deletes them, because a concurrent initializer could have committed. Only the owned unpublished temporary name is cleaned. Existing permissive user databases remain on their legacy mode-preserving path: no new0600 auxiliary guarantee is claimed for an existing0644 MAIN. Existing private0600 databases in unsafe parents or with unsafe sidecars now fail clearly; this is deliberate safety admission, not a permissions migration.

MCP returned `enforced (Landlock, ABI 3 or newer, fully enforced, canary verified)` in these live measurements. No insecure flag or model download was used. Test umasks are set only in freshly exec'd children; tests assert the parent test process's umask is unchanged.

Final `stat` alone is not the exposure proof. Native tests inspect the empty published inode before SQLite has opened it, and the production syscall traces show:

```text
mkdir(..., 0700)
openat(...temporary..., O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC, 0600) = 3
close(3) = 0
linkat(...temporary..., ...mind.db..., 0) = 0
unlink(...temporary...) = 0
openat(...mind.db..., O_RDWR|O_NOFOLLOW|O_CLOEXEC) = 3
openat(...mind.db-journal..., O_RDWR|O_CREAT|O_NOFOLLOW|O_CLOEXEC, 0600)
openat(...mind.db-wal..., O_RDWR|O_CREAT|O_NOFOLLOW|O_CLOEXEC, 0600)
openat(...mind.db-shm..., O_RDWR|O_CREAT|O_NOFOLLOW|O_CLOEXEC, 0600)
```

Thus the published MAIN is the already-private inode; there is no broad-mode creation followed by protective chmod. Auxiliary creation initially requests0600. Umask000/022/077 cannot widen those requests. This syscall/source argument covers the inaccessible interval that polling cannot establish.

Demonstrated scope is ordinary local Linux Unix permissions on the qualified filesystem with root and the database-owning UID trusted. Other UIDs cannot replace admitted parents or preplant absent auxiliary names. Hostile same-UID/root actors, malicious FUSE/NFS servers, arbitrary mount remapping, or operator permission changes after admission are not isolated. These are explicit assumptions, not properties established by a finite test run. Existing public parents may reveal filenames/metadata; file-content privacy is not a claim that every ancestor is hidden.
