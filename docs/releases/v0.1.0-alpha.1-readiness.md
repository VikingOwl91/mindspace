# v0.1.0-alpha.1 — Public Alpha readiness

Assessment date: 2026-11-12. This is a bounded source, test and release-gap assessment, not release approval. No production implementation, schema change, active fence, publication or ownership transfer was performed.

**Overall: BLOCKED for the requested milestone with completed canonical Document Ingestion.** Existing memory, lexical retrieval and Git ingestion provide a credible smaller Alpha, currently **PARTIAL** pending release qualification and hardening. M8 document extraction and private staging are substantial implemented foundations, but do not provide supported file-to-search ingestion. PDF extraction is missing. Canonical document publication is **BLOCKED FOR ALPHA** by accepted R01–R17 requirements; a parser or a renamed legacy API cannot resolve that boundary.

The current architecture supports continuing document work without a generic redesign. Completion nevertheless requires additional publication engineering, including an unresolved compatibility contract after rejected S3e.4d. It is not a small final parser/wiring task. A smaller initial Alpha can ship earlier only by explicitly deferring that milestone; this report does not silently change the requested product goal.

### Branch decision

The broader repository does not have a public roadmap file: [README](../../README.md), lines 309–381, distinguishes implemented/experimental/planned capabilities. [M8 design](../design-m8-document-intelligence.md) and [ADR](../adr-m8-document-intelligence.md) describe a larger staged program, including future format adapters, worker integration and publication. Their designs and experiments are not delivered features. Local tags are only `v0.2.0` and `v0.3.0`; Cargo and README say internal version `0.5.0`, not the proposed public `0.1.0-alpha.1`.

**Recommended candidate starting line for the requested milestone: retain the existing M8 branch at the verified HEAD.** It contains the document foundations and accepted legacy correctness fixes in S3e.4a–4c. It is not an accepted RC and its branch name does not indicate publication completion. Normal opening initializes/upgrades schema 17, and administrative staging commands are compiled/reachable; they cannot be treated as nonexistent merely because they are outside promoted Alpha scope.

`main` is a plausible reference for a smaller legacy/Git Alpha, not evidence of a complete document milestone. Git implementation itself is already on main. A main-based alternative would avoid migrations 10–17 but also omit the newer legacy settings/read-session/observation fixes; selecting/backporting those changes creates a new candidate requiring review and qualification. No reset, backport, merge or branch change is recommended automatically. Retaining the current line avoids that extra integration step; accepting its schema/admin surface remains a release gate.

## 3. Git-ingestion readiness

**Intended Alpha capability: CONDITIONAL, with a clear path to IN.** Git does not depend on M8 publication. Preserve the distinction between ordinary legacy repository ingestion and experimental isolated tools.

| Surface | Actual behavior | Alpha condition |
| --- | --- | --- |
| CLI `mind ingest <repo> --space …` | `src/cli/mod.rs:496–519` calls `ingest_paths`; default HEAD and live worktree HEADs, optional refs/history/path selection (`src/ingest/mod.rs:30–52`). Reads committed content, not dirty files. | Advertise local SHA-1 repositories, Rust symbols and legacy Markdown/text memories; verify exact candidate. No blanket arbitrary-repository memory-budget guarantee. |
| Ordinary MCP `repo_outline` / `repo_ingest` | Authorized roots and descriptor confinement; ingest requires RW root and Linux. Default requires verified sandbox; explicit `--insecure-no-sandbox` permits application-only operation with warnings (`src/cli/mod.rs:1117–1124`; `src/mcp/repo_tools.rs:352–365`). No roots means no repository access. | Exercise actual client and default Landlock refusal. Explicit insecure mode stays outside promoted Alpha guarantees; it remains reachable. Read-only root is not silently upgraded. This is not the broker worker. |
| `repo_ingest_git_isolated` | Hidden experimental tool requiring opt-in flags, approved Git executable, enforced sandbox and live broker. `src/cli/mod.rs:331–340,1006–1033,1156–1170`; `src/mcp/tools.rs:38–46`; `src/mcp/isolated_git.rs:1–48`. | OUT of promoted first-Alpha support. Default absence and fail-closed behavior must be verified; its implementation still exists in an ordinary binary. |

The ordinary Git reader scrubs inherited Git variables and disables helpers, hooks, replace refs, global/system config and network protocols (`src/ingest/git.rs:720–769`). Repository config and ordinary layout inputs are not equivalent to the stricter isolated layout. SHA-256 repositories are refused (`src/ingest/mod.rs:639–642`; `tests/git_object_format.rs:103–135`).

Repository UUID lives in `.git/mindspace-repository-id` (`src/ingest/git.rs:163–184`). Moves preserve it; a new clone normally has another identity. It does not authenticate repository origin. Marker creation can precede space validation: failed preparation can leave that repository marker despite zero DB writes. Atomic database ingestion is not a claim of zero filesystem side effects.

Combined Git observation, code derivation and resolution commit in one transaction/recording revision (`src/ingest/extract.rs:166–201`; `src/storage/mod.rs:134–164`). `tests/git_persist_atomicity.rs:263,307,351,434,453,478` covers rollback, veto and uncertain acknowledgement. `CommitOutcomeUnknown` is not rollback. A multi-root invocation can commit an earlier independent observation before a later failure (`src/ingest/mod.rs:350–355,404–409`).

Stored Git provenance includes full commit/blob OIDs, repository identity and path; current views retire stale memories and preserve historical evidence (`src/storage/sqlite.rs:5168–5275,5374–5460`). This is commit-scoped knowledge, not arbitrary cross-commit belief equivalence. Test cases cover unchanged ingest, fast-forward/rewrite, refs removed/reused, deleted paths, tags, worktrees and credential stripping (`tests/git_ingest.rs:543–1538`; `tests/git_hardening.rs:276–539`).

Resource limits are uneven. CLI ordinary ingestion has no operation deadline; ordinary MCP has a 30-second preparation deadline and refuses unscoped ingestion above 2,000 ingestable files. Persistence intentionally finishes beyond that deadline. Ordinary Git output/text collections are buffered without aggregate operation byte limits (`src/ingest/git.rs:900–970`; `src/ingest/mod.rs:678–699,749–755`). Current Rust structural policy has 2 MiB input/depth 256/32 MiB output limits (`src/ingest/code.rs:33–48`); old stack-overflow experiments are not proof of a current unfixed crash. Worker stream budgets do not protect the ordinary path.

Historical M7.3b.5e records 936 passed/0 failed/4 ignored, repeated/release runs and systemd containment (`docs/m7.3b5e-mcp-git-tool.md:115–123`). That is not qualification of HEAD. Current tests sometimes return early when broker/watchdog/Landlock prerequisites are absent (`tests/mcp_git_isolated.rs:294–314`; `tests/git_broker_mcp.rs:192–204`; `tests/git_confined.rs:30–39`). Record executed scenarios and skips, not only green Cargo totals.

Required gate: fresh DB→space→CLI and ordinary MCP ingest→lexical/code search→full provenance inspection→exact repeat→changed/deleted file/ref→correct current and historical results; persistence-failure rollback and retry; missing Git/SHA-256/read-only-root/denied-sandbox/timeout cases. Use a bounded fixture, document resource limits and measure a representative repository. If isolated tools stay OUT, delegated cgroups and systemd worker deployment are not mandatory user dependencies.

## 6. Proposed exact Alpha scope

| Feature | Disposition | Exact supported boundary / gate |

| Spaces/imports, explicit membership, conflict listing | IN | Retrieval organization; no ACL or automatic semantic conflict-resolution claim. |
