# v0.5 relationship model

Raw observations are immutable children of a code parser derivation. v0.5
uses `imports`, `calls`, and `implements`; existing entity parent paths remain
the one containment representation. A raw observation is identified by its
parser derivation, kind, byte range, and raw target syntax. It records its
enclosing entity when syntax provides one.

Resolution is a separate immutable derivation keyed by repository, commit,
resolver id/version, and the source parser derivation. Its result is
`resolved`, `unresolved`, `ambiguous`, or `external`. A resolved result has
one target entity; ambiguous results retain sorted candidate entity ids;
external results retain only raw syntax. A candidate is not an edge.

`mind-rust-resolver@1` resolves only a deliberately small Rust subset: local
free-function calls and absolute `crate::module::item` paths where the
repository/commit module index has exactly one matching entity; `use` paths
using `crate`, `self`, and `super` are internal only when that same index
proves a unique target. Method calls requiring receiver type inference stay
unresolved. `impl Trait for Type` is an observation and independently resolves
each named side only when unique. Globs, Cargo-dependent modules, macros, and
external crates are never guessed.

The commit, not a branch name, is the resolution context. Raw syntax for a
blob is reusable across paths and commits. A new commit gets a fresh resolver
derivation because a changed surrounding module can alter a result even when
the caller blob is unchanged. Another ref at the same commit reuses it.
Resolver/parser upgrades add sibling derivations. No relationship is an
Evidence, Assertion, or Memory, and no relationship establishes durable
cross-commit symbol identity.
